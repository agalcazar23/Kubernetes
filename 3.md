
# 📦 3. PODS en Kubernetes - Guía Visual para Principiantes

Una guía clara, directa y visual para entender **qué es un Pod**, cómo crearlo, inspeccionarlo, ver su página web y entrar dentro de él como si fuera una máquina Linux.

---

## 💡 ¿Qué es un Pod en 30 segundos?

* En Kubernetes **nunca lanzas un contenedor suelto**. Siempre va dentro de un **Pod**.
* Piensa en el Pod como una **"cápsula" o "vaina"**: le da al contenedor una dirección IP propia, almacenamiento y lo vigila para que no se caiga.
* En el 95% de los casos: **1 Pod = 1 Contenedor**.

---

## 🧭 Paso a Paso de la Práctica

---

### Paso 1: Crear un Pod "a lo rápido" (Modo Imperativo)

El modo imperativo es escribir una orden directa en la terminal sin ficheros de por medio. Es ideal para pruebas rápidas.

```bash
kubectl run pod-nginx --image=nginx
```
> **¿Qué hace?** Le pide a Kubernetes: *"Oye, descárgate la imagen oficial de Nginx y arranca un Pod que se llame `pod-nginx`"*.

Comprobamos que se ha creado con:
```bash
kubectl get all
```

![Creación del pod de forma rápida](img/01-run-pod.png)

#### 🧐 ¿Qué nos dice la pantalla?
* **`pod/pod-nginx`**: Nombre de nuestro Pod.
* **`READY 1/1`**: Significa que había 1 contenedor dentro y ya está 100% listo.
* **`STATUS Running`**: El servidor web ya está funcionando.
* **`service/kubernetes`**: Es un servicio interno propio de Kubernetes (no te preocupes por él ahora).

---

### Paso 2: Borrar el Pod

Para aprender la forma profesional (mediante archivos), primero borramos el que acabamos de crear para no tener nombres duplicados.

```bash
kubectl delete pod/pod-nginx
```

Y verificamos de nuevo con `kubectl get all`:

![Borrado del pod](img/02-delete-pod.png)

> ✅ **Resultado:** El Pod ha desaparecido y el clúster vuelve a estar limpio.

---

### Paso 3: Crear el Pod "como un profesional" (Modo Declarativo)

En el mundo real no se usan comandos largos en terminal; guardamos la configuración en un archivo `.yaml` (*Infraestructura como Código*).

Tenemos el archivo `pod.yaml`:
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod-nginx
  labels:
    app: nginx
    service: web
spec:
  containers:
    - image: nginx:1.16
      name: contenedor-nginx
      imagePullPolicy: Always
```

> 🔍 **Los 4 campos clave del YAML:**
> 1. **`apiVersion: v1`**: La versión estándar de Pods en Kubernetes.
> 2. **`kind: Pod`**: El tipo de recurso que queremos crear.
> 3. **`metadata`**: El DNI del Pod (`name: pod-nginx`) y sus etiquetas (`labels`) para clasificarlo.
> 4. **`spec`**: Lo que lleva dentro (un contenedor con la versión fija `nginx:1.16`).

Para aplicarlo ejecutamos:
```bash
kubectl apply -f pod.yaml
kubectl get all
```

![Creación mediante YAML](img/03-apply-yaml.png)

> 🚀 En solo 7 segundos (`AGE 7s`), Kubernetes leyó el fichero y dejó el Pod en `Running`.

---

### Paso 4: Mirar qué pasa "por debajo" (`kubectl describe`)

Si alguna vez un Pod no arranca o quieres saber qué pasos hizo el clúster, este comando es tu mejor amigo:

```bash
kubectl describe pod/pod-nginx
```

![Inspección detallada con describe](img/04-describe-pod.png)

#### 📋 En la sección **Events** vemos la película completa:
1. **Scheduled**: El planificador (*scheduler*) asignó el Pod al nodo `minikube`.
2. **Pulling / Pulled**: Kubelet descargó la imagen `nginx:1.16` en 3.2 segundos.
3. **Created / Started**: Creó el contenedor y lo arrancó con éxito.

---

### Paso 5: Abrir la web en el navegador (`kubectl port-forward`)

Por seguridad, los Pods no están abiertos a internet por defecto. Para ver nuestra web desde nuestro PC local, hacemos un "túnel" temporal:

```bash
kubectl port-forward pod/pod-nginx 8088:80
```
> **¿Qué hace?** Conecta el puerto `8088` de tu máquina real con el puerto `80` (el puerto web del Pod).

![Túnel port-forward](img/05-port-forward.png)

Ahora abrimos el navegador y entramos en `http://localhost:8088`:

![Web Welcome to nginx en el navegador](img/06-browser-nginx.png)

> 🎉 ¡Funciona! Estamos viendo la página de bienvenida de Nginx servida directamente desde nuestro Pod de Kubernetes.

---

### Paso 6: Ver los registros de visitas (`kubectl logs`)

Igual que en un servidor tradicional revisas `/var/log/nginx/access.log`, en Kubernetes se hace en un segundo con:

```bash
kubectl logs pod/pod-nginx
```

![Logs del servidor web](img/07-logs-pod.png)

> 👁️ **Fíjate en las líneas:**
> * `GET / HTTP/1.1 200`: La visita que acabamos de hacer desde Firefox (código `200 OK`).
> * `GET /favicon.ico 404`: El navegador intentó cargar el icono de la web y devolvió `404 Not Found`.

---

### Paso 7: Meterse dentro del contenedor (`kubectl exec`)

¿Necesitas entrar a trastear como si estuvieras por SSH? Puedes abrir una consola interactiva (`bash`):

```bash
kubectl exec pod/pod-nginx -it -- /bin/bash
```

![Entrando a la shell interactiva](img/08-exec-bash.png)

El prompt cambia a `root@pod-nginx:/#`. ¡Ya estamos dentro del contenedor!

Una vez dentro, comprobamos el sistema operativo del contenedor:
```bash
cat /etc/os-release
uname -a
ls
```

![Comandos dentro del contenedor](img/09-exec-inside.png)

> 💡 **Descubrimiento:** Vemos que la imagen de Nginx corre sobre un sistema base **Debian 10 (buster)** con su propio árbol de directorios aislado (`/bin`, `/etc`, `/var`...). Para salir solo escribes `exit`.

---

### Paso 8: Comprobación final de estado

Revisamos que tras todas nuestras pruebas el Pod sigue funcionando como un reloj:

```bash
kubectl get all
```

![Estado final del pod](img/10-get-all-status.png)

> ⏱️ El Pod lleva ya 13 minutos (`AGE 13m`), con `0` reinicios (*RESTARTS 0*) y sigue en perfecto estado `Running`.

## 📌 Chuleta Resumen de Comandos

| Comando | ¿Para qué sirve? |
| :--- | :--- |
| `kubectl run <nombre> --image=<img]` | Crear un Pod rápido (modo imperativo) |
| `kubectl apply -f fichero.yaml` | Crear o actualizar un Pod desde un archivo YAML |
| `kubectl get all` | Ver todos los recursos activos (Pods, servicios...) |
| `kubectl describe pod <nombre>` | Ver información detallada y eventos de arranque |
| `kubectl port-forward pod <p_local>:<p_pod>` | Conectar un puerto de tu PC al Pod para probarlo |
| `kubectl logs <nombre>` | Ver los logs y accesos del contenedor |
| `kubectl exec -it <nombre> -- /bin/bash` | Abrir una terminal dentro del contenedor |
| `kubectl delete pod <nombre>` | Eliminar el Pod |
